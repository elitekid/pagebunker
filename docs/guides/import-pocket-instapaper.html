보관 중인 Pocket·Instapaper 파일을 PageBunker로 가져오기

내보내기 파일의 링크를 옮기고, 읽을 글의 본문을 따로 저장하는 순서입니다.

이 문서는 PageBunker 제작자가 작성했습니다. 제품 설명 확인일과 실제 시험일을 구분해 기록합니다. 경쟁 도구는 같은 조건을 충족하는 경우에만 비교합니다.

자료 조사·제품 설명 확인일: 2026-09-18 · 실제 시험일: 이번 문서 작성에서는 실사용 시험을 수행하지 않았습니다.

Import an existing Pocket CSV or legacy HTML export, Instapaper CSV, or browser bookmarks HTML into PageBunker. Imports add links, not article bodies; save each accessible original page to read its text offline. Images are not archived offline. Pocket exports ended on November 12, 2025. This maker-written guide is based on documentation reviewed on September 18, 2026, not a hands-on test.

1. 지금 가능한 이동과 불가능한 복구

이 가이드는 이미 가지고 있는 내보내기 파일을 옮기는 절차입니다. Pocket 내보내기는 2025년 11월 12일 종료됐으므로 지금 Pocket에 접속해 새 파일을 받는 방법은 제공하지 않습니다. 종료 일정의 근거는 Mozilla의 Pocket 종료 안내입니다.

파일에 남은 링크를 PageBunker로 가져오는 것과 그 링크의 본문을 확보하는 것은 다른 작업입니다. 링크를 옮겨도 이미 사라진 원문이 복구되지는 않습니다.

2. 파일 고르기

Pocket ZIP을 보관하고 있다면 압축을 풀고 CSV를 선택하세요. 가져올 수 있는 형식은 다음과 같습니다.

  • Pocket 내보내기 CSV
  • Pocket 옛 HTML 내보내기 파일
  • Instapaper CSV
  • 브라우저 북마크 HTML

PageBunker 백업 JSON은 가져오기 파일과 다른 복원용 파일입니다. 예를 들어 pagebunker-latest.json은 기존 PageBunker 보관함을 복원할 때 사용합니다.

Instapaper는 이미 보유한 CSV를 선택하는 절차만 안내합니다. 공식 내보내기 도움말에 CSV 설명이 있지만, 로그인 후 현재 메뉴 경로와 실제 다운로드는 확인하지 않았으므로 메뉴 경로를 적지 않습니다.

지원 형식 근거: PageBunker 공식 README의 가져오기·내보내기.

3. 가져오기 전 보관함 보호

기존 PageBunker 보관함이 있다면 Downloads/PageBunker/pagebunker-latest.json을 다른 폴더에도 복사한 뒤 진행하세요. 가져오기와 백업 복원은 다른 작업입니다.

작업 중인 보관함은 브라우저 안에 있고, 글이 바뀌면 다운로드 폴더의 백업 파일도 갱신됩니다. 가져오기 전 사본을 별도로 보관하면 이후 갱신되는 백업과 구별할 수 있습니다.

이 글의 툴바 저장 안내는 PageBunker 1.1.0 설명 기준입니다. 2026-09-18 기준 엣지는 1.1.0 공개, 크롬은 1.0.0 공개·1.1.0 심사 중이며 파이어폭스 등록 페이지는 아직 공개되지 않았습니다. 크롬에서는 해당 업데이트 공개 후 툴바 안내를 따라 주세요. 이 상태는 공식 README의 확인일 기준 기록입니다.

4. 미리보기와 확정

  1. PageBunker 보관함에서 가져오기(Import)를 엽니다.
  2. 준비한 CSV 또는 지원되는 HTML 파일을 선택합니다.
  3. 미리보기의 제목과 링크를 살펴보고, 옮기려던 파일인지 확인합니다.
  4. 내용을 확인한 뒤 가져오기를 확정합니다.

중복 링크 처리 방식, 지원 필드의 상세 목록, 오류 파일 처리 동작은 이번 자료 확인으로 확정하지 않았습니다. 태그나 읽음 상태가 모두 이전된다고 보장하지 않습니다.

미리보기와 가져오기 절차 근거: PageBunker 공식 README. 배포본의 화면·동작을 이번 작성에서 직접 대조한 것은 아닙니다.

5. 링크에 본문 채우기

가져온 항목에는 링크만 있습니다. 접속 가능한 원문을 열고 PageBunker의 ‘이 글 저장’을 실행해야 본문이 들어옵니다. 가져오기가 원문 본문을 자동으로 일괄 다운로드하지는 않습니다.

원문이 열린 탭에서 툴바 버튼을 누른 뒤 ‘이 글 저장’을 선택하세요. 페이지 우클릭 메뉴의 ‘이 글 저장’이나 Alt+Shift+L(맥은 Option+Shift+L)도 사용할 수 있습니다. 본문 추출에 실패하면 링크만 저장됩니다.

이미 사라진 원문을 내보내기 링크만으로 되살릴 수는 없습니다. 본문이 저장되었는지는 보관함의 읽기 화면을 열어 확인하세요.

본문 저장·추출 실패 동작 근거: PageBunker 공식 기능 설명.

6. 오프라인 읽기와 검색 확인

다음은 독자가 확인할 수 있는 절차이며, 이 글에서 수행한 시험 결과가 아닙니다.

  1. 제목에는 없고 본문에만 있는 한글·영어 구절을 고릅니다. 링크 가져오기 직후와 본문 저장 후에 각각 보관함에서 검색해 결과를 구분해 기록하세요.
  2. 본문을 저장한 뒤 네트워크를 끊고 보관함에서 글을 다시 열어 글자가 보이는지 확인하세요.
  3. 본문이 저장된 항목과 링크만 있는 항목을 따로 기록하세요. 링크만 있는 항목에는 오프라인으로 읽을 본문이 없습니다.

PageBunker의 한국어·영어 검색 대상은 저장한 본문과 제목·사이트·태그입니다. 아직 저장하지 않은 원문 본문까지 검색하지는 않습니다.

이미지는 오프라인 보관 대상이 아닙니다. 기본으로 불러오지 않으며, 이미지 보기나 원문 열기는 해당 사이트에 연결해야 합니다. 저장된 글자의 오프라인 읽기와 이미지 표시를 같은 결과로 기록하지 마세요.

검색·오프라인 조건 근거: PageBunker 공식 README. 시험할 때에는 제품 버전, 브라우저 버전, 시험 날짜, 예시 문서와 실제 결과를 함께 남기세요. 이번 문서에는 실사용 시험일·결과가 없습니다.

7. 잘못 가져왔을 때

가져오기 작업 전체를 되돌릴 수 있습니다. 이는 PageBunker 백업 JSON으로 보관함을 복원하는 작업과 구별됩니다.

백업 JSON으로 복원할 때에는 병합과 교체를 구분해 선택하세요. 교체 복원은 한 번 되돌릴 수 있습니다. 확장을 지운 경우에는 다시 설치한 뒤 남아 있는 백업 파일로 백업된 보관함을 복원할 수 있습니다.

되돌리기·복원을 시험하려면 별도 브라우저 시험 프로필의 예시 데이터에서 확인하세요. 이 글에서는 실제 배포본의 세부 메뉴 위치나 확인 창을 검증하지 않았습니다.

작업 단위 되돌리기·복원 방식 근거: PageBunker 공식 README.

8. 해결하지 못하는 경우

파일이 없거나 원문에 접근할 수 없으면 본문 이전이 제한됩니다. 원문에 접근할 수 있어도 본문 추출에 실패하면 링크만 남습니다. 이미지는 오프라인 보관되지 않습니다.

PageBunker는 기기 자동 동기화나 모바일 앱을 제공하지 않습니다. 다른 컴퓨터로 옮기려면 백업 JSON을 직접 복사해 복원할 수 있지만, 이는 자동 동기화가 아닙니다. 백업도 파일 삭제나 디스크 고장을 막아 주지는 않으므로 필요한 사본은 따로 보관하세요.

보관 방식부터 고르고 싶다면 계정 없이 나중에 읽기 — 로컬 확장·파일 저장·서버형 도구 비교를 읽어 보세요.
